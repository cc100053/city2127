# 2127 — Frozen Intersection

**言語：** [繁體中文](README.md) · [English](README.en.md) · [日本語](README.ja.md)

## 作品について

「100年後の街は、誰が決めるのでしょうか。」これまで街のかたちは、行政や大企業によって決められてきました。そこに住む住民が決めることは、ほとんどありませんでした。もし100年後の未来を住民が決めるとしたら、街はどうなるのでしょうか。この展示は、その可能性を考える試みです。来場者は2127年のお台場に暮らす一人の住民として日々の暮らしの希望に答え、その声がほかの住民の声と重なって、次の来場者が受け継ぐ街になります。一人の答えだけで街が決まることはありません。大画面の最初のカード `intro.origin` も同じ問いから世界観に導きます（[RESIDENT_COPY](docs/RESIDENT_COPY.md)）。

- 各来場者は四つの質問に答え、一つの提案を送信します。次の来場者は、それまでの選択が反映された街を引き継ぎます。
- 展示用の街はリポジトリ直下の Three.js シーン（`src/`）です。
- `survey/` サーバーが質問、状態、SQLite データベース、WebSocket 配信を管理します。
- `module-swap/` は旧 v1 の因果デモで、現在の v2 CityView には対応していません。

## 展示を起動する（Mac / Windows）

- Git と **Node.js 24 以上**（npm を含む）、WebGL 2 対応のデスクトップブラウザーが必要です。
- 特記がなければリポジトリのルートから実行し、二つのターミナルタブは起動したままにします。
- `npm ci` は初回と lockfile 更新時に実行します。通常の再起動ではタブ 1 の build／server とタブ 2 の dev だけを実行します。
- ローカルの展示用の手順です。公開デプロイの設定はありません。

### Mac — ターミナルを二つ開く

**タブ 1：アンケートサーバー** — API、WebSocket、guest／monitor／admin 画面、SQLite の状態を提供します。起動前に画面をビルドします。

```sh
cd survey
npm ci
npm run build
npm run server
```

**タブ 2：3D の街** — リポジトリのルートで新しいタブを開きます。Vite が Three.js シーンを提供します。

```sh
npm ci
npm run dev -- --port 5173
```

### Windows — PowerShell を二つ開く

**タブ 1：アンケートサーバー** — リポジトリのルートから開始します。

```powershell
Set-Location survey
npm ci
npm run build
npm run server
```

**タブ 2：3D の街** — リポジトリのルートで別の PowerShell タブを開きます。

```powershell
npm ci
npm run dev -- --port 5173
```

- サーバーの標準アドレスは `127.0.0.1:8787`、ルートの Vite は `127.0.0.1:5173` です。
- Vite が別のポートを表示した場合、街には実際に表示された URL を使います。サーバーのポートを変えた場合は、街の URL に WebSocket の URL を明示します。

### ブラウザーのタブと画面

| タブ | 標準 URL | 役割 |
| --- | --- | --- |
| Guest（単独） | `http://127.0.0.1:8787/guest` | 四つの質問への回答、確認、一つの提案の送信。 |
| Guest A/B（2台） | `http://<展示PCのLAN IP>:8787/guest?station=A` ／ `?station=B` | 独立した四問の体験で同じ街に提案します。 |
| City | `http://127.0.0.1:5173/?survey` | 展示用の 2127 年のお台場。`ws://127.0.0.1:8787/ws` から変化を受信します。`?survey` を付けて開きます。 |
| Admin | `http://127.0.0.1:8787/admin` | スタッフが状態を確認し、未完了の体験を終了し、リセットを要求・取消します。サーバー PC の localhost からのみ利用可能です。 |
| Monitor（任意） | `http://127.0.0.1:8787/monitor` | 現在の状態と、画面を開いてから受信した提案・WebSocket イベントを文字で確認する画面。3D の街ではありません。 |

- City を展示スクリーン、Guest を入力スクリーンで開き、Admin はスタッフ用 PC に置きます。
- City に別のホストやビルドは不要です。タブ 2 の Vite が提供します。
- Guest／Admin／Monitor と API はサーバーが同じ origin で提供するため、先に `npm run build` を終えておく必要があります。
- 標準の DB は `survey/data/survey.sqlite` で、サーバーを再起動しても街の状態は残ります。

### 単独モードの交代とリセット

以下は単独 `/guest` の規則です。2台の場合は下の A/B の節を参照してください。

- 提案後、Guest は通常どおり結果と交代の画面を表示します。
- 次の来場者が **はじめる** を押すと自動で交代します。Admin の退出確認は不要です。
- リセットがなければ街を引き継ぎ、保留中のリセットは次の開始時に実行されます。
- Admin の **未完了の体験を終了** は、未完了の質問を中止し、保留中のリセットを実行するための操作です。

### Admin の昼夜設定

- Admin の **昼／夜／自動** で、接続中の City を 12:00／22:00 に固定するか、昼夜の循環に戻せます。
- 設定は保存され、提案やスコアには影響しません。
- 街の URL に `?hour` があれば、そちらが優先されます。
- この機能の更新後は survey サーバーを再起動し（既存の SQLite は保持）、Admin を更新してください。

### LAN 上の別端末

- **信頼できる同一 LAN** の別端末で Guest／City を開く場合は、survey を LAN に公開します。Vite は City を別端末で開く場合だけ公開します（City をホストで開くなら loopback のままで構いません）。Guest と City の URL の `127.0.0.1` はホスト PC の LAN IP に置き換えます。

```sh
# Mac: survey/ で実行（タブ 1）
SURVEY_HOST=0.0.0.0 npm run server
# リポジトリのルートで実行（タブ 2）
npm run dev -- --host 0.0.0.0 --port 5173
```

```powershell
# Windows PowerShell: survey/ で実行（タブ 1）
$env:SURVEY_HOST='0.0.0.0'; npm run server
# リポジトリのルートで実行（タブ 2）
npm run dev -- --host 0.0.0.0 --port 5173
```

- 両ポートに接続できる必要があります。Admin は引き続きサーバー PC の localhost 専用です。
- 標準の loopback 設定はこの PC 専用です。Guest には認証がないため、信頼できる展示 LAN で利用してください。
- 例えばサーバーを 8790 番で動かす場合、街の URL は `http://127.0.0.1:5173/?survey=ws://127.0.0.1:8790/ws` です（LAN ではホスト名も置き換えます）。

### 直前の提案の取り消し（Undo）

- Admin の **直前の提案を取り消す** は、直前に完了した提案だけを、次の来場者が開始する前に取り消します。
- 変更前の街と参加人数を復元し、元の提案は取消済みとして保存します。Guest は新しい四問の体験として再回答できます。
- A/B の新しい草稿を開始した後は、その草稿を中止しても古い提案の Undo は再び使えません。
- 更新後は survey を再ビルド・再起動し、City／Guest／Admin を更新してください。
- Undo は schema 6 で導入されました。現在の SQLite はデータを削除せず schema 7 に移行します。

### 2台で同時に回答（2026-10-02）

- 同じ信頼できる LAN の survey server を使い、1台で `http://<展示PCのLAN IP>:8787/guest?station=A`、もう1台で `/guest?station=B` を開きます。
- サーバーは上の LAN の手順で起動します。City を展示 PC で開くなら、ルートの Vite は loopback のままで構いません。
- `SURVEY_HOST=0.0.0.0` で起動すると、サーバーが A/B の `LAN Guest:` URL を表示するので、そのまま iPad に入力します。ルーター／iPad の設定は [LAN 2台 handoff](docs/handoffs/lan-guest-stations.md) を参照。
- 各ステーションの草稿・四問・結果・交代は独立し、片方が終わってももう片方は消えません。
- 提案はサーバーの受信順に累積し、再送は一度だけ加算します。
- 各ステーションは同時に1体験です。同じステーションのページを複数開かないでください。
- 既存 `/guest` の単独モードは維持しますが、体験中の A/B と混在させないでください。
- City の結果は記録順に10秒以上の閲覧枠を取り、街の変化は3秒、提案番号と A/B を表示します。
- 待機中の Guest は「保存済み・展示待ち」を表示し、その後に自分の結果10秒／交代5秒を表示します。
- City の再接続は最新の完全な状態をすぐに復元します。
- A/B のリセットは新しい開始を止め、両方の回答と結果・交代が終わってから実行します。Admin は **A／B の未完了の体験を終了** で片方だけ終了できます。
- 通信が切れたステーションは、回答開始から5分、または記録済みの結果のリース（展示開始から15秒）の終了で解放されます（結果の復元は元の枠の残り時間を引き継ぎ、リースは延長しません）。Admin の退出確認は不要です。
- City リセットは累計人数を保持し、全リセットは累計を0にしますが履歴は残します。
- 更新後は survey を再ビルド・再起動し、Guest／City／Admin を更新してください。SQLite は schema 7 に移行し、既存の街と履歴を保持します。
- 実装と検証：[2台 handoff](docs/handoffs/archive/two-guest-devices.md)。

### 開発用の自動回答（DEV-ONLY、2026-09-30）

- `survey/` で `npm run dev:auto` を実行し、`http://127.0.0.1:8788/guest?dev-auto` を開きます。
- 街の Vite は起動したまま、`http://127.0.0.1:5173/?survey=ws://127.0.0.1:8788/ws` に接続します（Vite のポートが違えば置き換え）。
- 起動のたびに新しい独立したテスト用 SQLite を作り、場所をターミナルに表示します。展示用の `survey/data/survey.sqlite` は変更せず、テスト用データは確認用に残します。
- パネルでは、全部 −1／0／+1、順番に混ぜる、物差しごとに指定、シード付きランダムを選び、提案数を決めて **自動回答を開始** を押します。
- 標準は10件、シード2127。通常の Guest の草稿／確認／送信を使い、1問0.3秒、結果10秒、交代5秒で開始画面に戻ります。次の提案の開始時に自動で交代します。
- 停止やエラーの後は次の提案を作りません。送信済みのリクエストは完了し、結果不明のものは同じ ID で再送します。
- 通常の `/guest` にはパネルは表示されません。
- localhost 専用で、サーバーに `SURVEY_DEV_AUTO=1` が必要です（起動スクリプトが設定します）。
- 別の来場者、競合、保留中のリセットがあると停止し、自動でリセットはしません。
- **展示前に DEV-ONLY のパネル／endpoint／起動スクリプトを削除するか、Admin に移してください。単独モードは承認済みの自動交代のままで、古い退出ロックは戻しません。** コードの入口と[仕様書](docs/EXHIBITION_SPEC.md#開發工具與待完成驗收)に `DEV-ONLY` の削除／移行の注記があります。詳細は[アンケートの説明](survey/README.md)。
- 物差しのテストだけを実行：`cd survey && npm run test:meters`。全体の連携はルート／survey の `npm test` に含まれます。

## 現在の街と範囲

- 展示の街は **2127 年のお台場の海辺** だけです。
- 渋谷は終了した過去の決定で、今後は開発しません（2026-10-02）。会場の切り替えはなく、旧 Plan 01／02 とスクリーンショットは履歴であり、未完了項目は今後のタスクではありません。
- ルート `src/` は Three.js / WebGL 2 で、お台場地区の地形、ランドマーク GLB 6棟、プログラムで作る civic core、周辺につながる静かな背景を読み込みます。
- 2127 年の skyways、潮の満ち引きのある水辺、6つの waterfront islands が現在の街にあります。150 m で島に溶けて消える初期版はもう使いません。
- 4つの物差しは中心地点と地区全体を同時に変え、low／mixed／high をどれも成熟した未来として保ち、hybrid、軸をまたぐ施設、履歴による配置に対応します。
- 街は1日180秒で自動的に昼夜が巡ります。`?hour=22` で時刻を固定できます。
- カメラ、共有マテリアル／InstancedMesh、3秒の変化、即時のリセット／再接続の実装は [PROJECT](docs/PROJECT.md) を参照。
- 後処理：MSAA、GTAO、bloom、vignette、output、色調補正。
- GPU が弱い PC（例：M1 で 4K モニター）では、街の URL に `&quality=low` を付けます。MSAA、GTAO、影をオフにし、pixel ratio の上限を1にします。標準の見た目は変わりません（2026-10-15）。

### 開発用の確認ツール

- `?meters=nw:high,ne:low`（band または −12..12）で v2 の配置を直接確認できます。
- コンソールの `cityMeters('ne:high')` で変化を確認し、`&metersTo=ne:high&metersAge=0.7` と `reviewTime` でスクリーンショットを撮ります。
- これらのツールは提案を送らず、展示データも変えません。
- `?asset-preview` でローカルの GLB を原点に読み込めます。別の素材は再読み込みして選びます。本番には選択画面はありません。素材の基準は [BLENDER](docs/BLENDER.md)。

### 住民 P2／P3 の更新（2026-10-02）

- P2：
  - 更新後は survey を再ビルド・再起動し、Guest／City を更新してください。
  - 四つの問いを日常の希望の文言に変え、確認は送信前に残しています。結果は保存／待機、ステーション／暮らしの声番号、街を見る案内だけを表示します。
  - City は背景／現在の施設と、控えめな記録確認を表示します。
  - Question-set version 3 でも SQLite と保存済み回答の原文は保持します。旧草稿は「新しい予約で草稿を続ける」で有効な選択を引き継ぎます。A/B は自分の旧予約を終了してから再予約します。
  - 3秒の変化／A-B の間隔、result 10秒／handoff 5秒は維持します。閲覧枠と変化の理由は P3 です。[P2 引き継ぎ](docs/handoffs/archive/resident-experience-p2.md)。
- P3：
  - survey を再ビルド・再起動し、Guest／City を更新してください。
  - 各回答に10秒の閲覧枠を予約します（0–3秒は識別／場所／街の変化、3–10秒は選んだ暮らしと街の実際の結果）。
  - A/B は順番を保ち、待機／早い交代／リセット／再送も元の枠を引き継ぎます。
  - 実際の carrier の配置で説明し、局所の増加から街全体や人口の増加を推論しません。
  - 再接続／Undo／reduced motion は即時に復元し、照明の変更は有効な表示を保ちます。
  - [P3 引き継ぎ](docs/handoffs/archive/resident-experience-p3.md)。P4／P5 は未検証です。
