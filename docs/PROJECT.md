## Product and package boundaries

The single exhibition venue is the **Odaiba waterfront in 2127**. Shibuya is a closed historical direction and will not be developed again (user decision, 2026-10-02). Historical unfinished tasks are not the current backlog. Legacy internal site IDs are compatibility identifiers, not a second venue.

| `survey/` | Proposal API, SQLite schema 9, WebSocket, Guest / Monitor / loopback Admin. The product is the nine-question rotation (below); the version4 four-question reducer and Meter layout are retired legacy, still the server default `SURVEY_QUESTIONS` until switched |

Desktop-only presentation, with normal renderer resize. Do not add adaptive camera/mobile acceptance. Ambient people, vehicles, drones and aerial routes are allowed. Every rotation option (A/B/C) depicts a mature 2127 alternative; the four-Meter version is retired (owner 2026-11-21). No deployment workflow is configured.

Resident [P1 copy](RESIDENT_COPY.md) is wired by [P2](handoffs/archive/resident-experience-p2.md). Guest handles questions/background, choices, review, save/wait/retry, shared station/ordinal identity and the look-up prompt; results have no answer/score/facility tables. The existing single-revision conflict review still displays scores for recovery. Question-set version **4** (energy E4, 2026-10-24) is independent of algorithm/CityView v2 and SQLite schema8; P2 introduced version3 copy. Older reserved drafts are rejected by the existing version guard, then valid choices can be carried into a fresh reservation; A/B ends its own obsolete reservation through the existing endpoint first. Stored version2 proposals retain their original question/option copy and remain idempotently recoverable after upgrade.

Root reuses `surveyAtmosphere`'s panel for one fixed desktop reading card at the top right (moved from the left 2026-10-04: at 1280–3840 px wide all four focal sites project left of it): title, at most two sentences and named location. Ambient background/facility cards rotate locally every12s; current-run proposals, never lifetime participation alone, allow the inherited-city card. Service/shared-seat counts, Park tree/cooling quantities and the tower's rendered band select focal facility descriptions. Even low Park retains trees, so trees+cooling uses the combined card; these are descriptions of current facilities, not district change inference. The rotation opens with `intro.origin` (who has decided cities so far; added 2026-10-19), then the identity card, whose body is shortened to its first two P1 sentences. P3 live results reserve10s: identity/location during the existing3s transition, then one selected preference plus one collective effect until the slot ends. `CityChangeManager.applyExhibitionLayout` returns focal/district evidence by comparing effective `getConfiguration()` targets, including slot distribution, rendered hybrids, visible pairing products, published roofs/facades and actual fleet counts. Hidden tower extras and seed changes alone are not visual evidence. Focal-only quantities name their own site; any district change (including simultaneous focal changes) uses district locations and conservative configuration wording. No evidence after a missed predecessor uses the recorded fallback; unchanged targets distinguish score-direction changes from maintained configuration. Snapshot/reset/Undo replaces the card immediately; reload does not replay an old result. Lighting-only snapshots do not restart cards or skip queued changes.

The [resident experience plan](history/RESIDENT_EXPERIENCE_PLAN.md) records P1–P3 implementation and [P4 software acceptance](handoffs/archive/resident-experience-p4.md); P5 device/visitor acceptance remains. `survey/src/shared/displayTiming.ts` supplies server/root/Guest reading10s, handoff5s and result lease15s separately from the renderer transition3s. Provisional iPad hardware/Safari/visitor understanding and whether ten seconds is sufficient remain unverified; no generic responsive requirement. Geometry/resources retain the existing pipeline. Live headline camera presentation is described below; server reading slots and leases are unchanged.

## Root source ownership

DEV 近鏡量度（closeup-polish S0）：`main.ts` 只在 `import.meta.env.DEV` 動態載入 [devShotFrame.ts](../src/devShotFrame.ts)，提供 `window.cityShotFrame(id)`。主體依現有名稱取 socket site root、district carrier 或能源 group；回傳可見 mesh／instance 的 world AABB 投影、九個內縮取樣點及第一個可見 mesh 命中。沒有主體或 bounds 跨 near plane 時明確回傳 null，不能當 framing PASS。沿用現有 test dependency `three-mesh-bvh` 的 indirect 精確 raycast，僅同步量度期間暫換並還原 Mesh raycast；不改 render loop 或 production。CPU raycast 不模擬 shader displacement／貼圖 alpha，因此是計劃的幾何取樣條件，並非逐像素可見性證明。

DEV 居民情景（2026-11-12，湊／NW focal）：`main.ts` 只在 `import.meta.env.DEV` 動態載入 [devMinato.ts](../src/devMinato.ts)（`?meters=nw:2&shot=nw:resident`，可加 `&kiosk=x,z&cam=px,py,pz,tx,ty,tz` 做鏡頭位勘察）及 [devResidentDemo.ts](../src/devResidentDemo.ts)（`?survey=…&residentDemo`）。後者在 live 結果的 headline 是 `nw:focal`／`nw:focal-low` 時，把 headline 鏡頭多留 `BEAT_SECONDS`（10 s），由建築變化完結起沿弧線移到居民鏡頭（FOV 52）、播一次行動、再返回；期間結果卡淡出、左下顯示一句字幕，任何新 survey 訊息都會取消。行動及鏡頭一拍是 [minatoTimeline.ts](../src/minatoTimeline.ts) 的純函數；人物及亭仔是 Blender 剛體分件 GLB（`asset/models/resident-minato`、`resident-kiosk`），由程式旋轉有名節點，沒有骨骼或 `AnimationMixer`。佈景、人物及鏡頭距離跟 hub 路人比例（+1 ×1.0、0 ×1.6、−1 ×2.6）放大。`SHOTS`、`shotTimeline` 及 production build 不受影響。詳見 [交接](handoffs/resident-minato.md)。

DEV `?rotation` holds a question-rotation run in the page instead of the server (`src/devRotation.ts`, built from the server's own `survey/src/shared/rotation.ts`); its panel `src/devRotationPanel.ts` lists the nine questions × three options, and each press plays one simulated guest choosing that option through the live path (vote orb, close-up, lot transition or concept hologram, result card). 「即時」 sets a modelled option at once and pins its close-up; `nopanel` hides the panel and `window.cityRotation('Q02','B')` plays one from the console. Other DEV comparisons retain their own camera.

Renderer: WebGL 2, Neutral tone mapping (.84 base exposure), sRGB output, pixel ratio capped at 1.5, VSM directional shadows. [renderQuality](../src/renderQuality.ts) reads `?quality=low` (2026-10-15, manual fallback for weaker GPUs, production too): pixel ratio cap 1, no MSAA, GTAO disabled and the shadow map off; the default keeps the full look and automatic quality stepping is not implemented. Since 2026-10-27 the default renders GTAO at half the canvas size (upsampled by its blend), uses 2× MSAA and redraws the shadow map 4 times per second on wall-clock time (the sun moves ~2°/s); `mobility.ts` fleets (people, vehicles, drones, boats, benches, guides) cast no shadows, while trees, buildings and Meter structures still do. The sky dome follows the camera. A softened generated sky plus RoomEnvironment light cards feeds PMREM reflections. Composer: 2× MSAA HalfFloat target → RenderPass → GTAO → bloom → vignette → OutputPass → display-space colour grade. Curved sea/bay context, wakes and Meter pulses are excluded where required from GTAO's flat override prepass. Do not add another tone-map/output conversion. Environment ground finishes lie within 0–3 cm of each other (building pads over lawn terrain, plazas, service yards), below hero-range depth precision; `odaibaScene` gives road/service, plaza, sidewalk and road-marking finishes increasing polygon offsets so they stack in that order over the lawn instead of z-fighting (2026-10-06).

Static groups are merged by material, windows/actors/carriers use InstancedMesh, and inactive district batches issue no draws. Shared resources are not disposed by a clone. Hidden transition transforms remain invertible. No geometry/material allocation per frame. Full teardown for repeated in-page scene recreation is not implemented; initialization is once per page.

## Frame and data flow

`main` determines clock/display hour → standalone `moodAt` or survey `world.state`, followed by `withNight`, supplies base atmosphere → lights/sky/fog update → `CityChangeManager.update(time,darkness)` advances focal sites, district carriers, pulses and local motion → `cityRig.update` forwards eased automation activity to mobility → `updateOdaiba` updates glazing → overlay and composer render. Time uses `performance.now()`; hidden tabs may advance motion on return.

A city day is 180 s from 12:00. Mood labels are Still / Daylight / Pulse; the old preset buttons and `0/1/2` controls were removed. `?hour=0..23.999` holds review time and overrides Admin Day/Night/Auto. Admin display setting persists independently of city reset. Separate Auto viewers have local clocks.

DEV-only `?energy=baseline|a|b|c|mixed`（配合`hour`／`reviewTime`）提供E3城市組合；只在沒有`survey`／`meters`／`scaleLab`時啟動。`startEnergyReview`回傳frame callback給現有`devFrame`，`energyPrototype.update(absoluteSeconds,reducedMotion)`同步兩水庭水位／管內流向、渦輪、富士前置環與兩處岸邊配電服務軌。60秒充能20／暫存20／釋能20；C配電獨立運作。36個合併／水面mesh與4個flow InstancedMesh一次建立，第二庭共用geometry／materials；只改可見性與transform／instance矩陣。系統reduced motion或原生「靜態閱讀」核取框固定本輪全部能源動態並保留箭頭／流程。Production移除DEV import／工具，正式四題及資料不變。[組合、座標、敘事／工程限制](history/ENERGY_CITY_PLAN.md#e3成果城市組合與慢速因果動態2026-10-24)，[實際桌面證據](../artifacts/energy-city-e3/README.md)。

Standalone uses day-cycle activity and does not create the v2 district layer. `?survey` connects to `ws://<current-host>:8787/ws`, or the explicit ws/wss URL supplied as its value. Legacy v1 retains the 10 s atmosphere path. Rotation views use the server rotation state and keep the day-cycle atmosphere independent from proposals.

## Performance diagnostics

City canvas diagnostics update every120 rendered frames: `data-fps` is the mean cadence over those120 frames; `data-draw-calls` and `data-triangles` are the last completed composer render (all passes), `data-geometries` / `data-textures` are renderer resource counts. They do not measure GPU allocation or per-frame latency. The optional [E5 browser runner](../tests/energyE5.browser.mjs) records separate rAF interval distributions, CDP JS heap and scratch-server RSS, using headed Chrome and real A/B Guest submissions; it adds no runtime dependency.
