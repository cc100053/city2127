## 方向

城市本身保持細緻（三個 Meter 位置都是成熟的 2127），戲劇性放在**居民的生活**上。每個投票結果的畫面次序：

投票 → 推近建築看變化 → 再推近看一位居民的行動。

每個變化單位分兩級進行，**上一級獲驗收後才做下一級**：

1. **階段 1 — 建築與變化元素。** 需要打磨的模型、鏡頭或轉場，先做到 owner 驗收。使用 [closeup-polish](../.agents/skills/closeup-polish/SKILL.md)。Owner 表示無須打磨的單位直接進入階段 2。
2. **階段 2 — 人物情景故事。** 一位有名有姓的居民，在人物尺度的佈景中，以行動演出這項變化對其一日的影響。使用 [resident-scene](../.agents/skills/resident-scene/SKILL.md)。

挑選下一個單位、判斷其所在級別、完成後更新下表：[polish-ladder](../.agents/skills/polish-ladder/SKILL.md)。

Owner 審閱用的總覽（選擇 → 變化說明 → 建築介紹 → 前後對照 → 居民）由程式生成：`node --experimental-strip-types scripts/changeSheet.ts` → `artifacts/change-review/index.html`。下方總表與居民表即其資料來源，修改本文件後須重新生成。

**為什麼移動模組適合她的生活**：她的職業是 2127 年才有的「配送航路編集者」：為全區的無人機與自動車編排每日航路，向各服務灣的營運者提案。她住在小房子，沒有工作間，而每天需要的場所不同：編航路的日子要安靜的工作間，與營運者對稿的日子要能圍坐的小會議室，街坊來看模擬航路的日子要能容納十來人的小廳。固定的庭園或廣場只能給一種；棚讓她**按當天需要呼叫一座小建築**，用完就運走，不必擁有，也不必遷就。她不評價哪一種較好，只是這一天剛好需要一間房。
