# Mind craft― 選択の積み重ねでつくる都市 ―

**「マイン」ではなく「マインド」クラフト**

この町お台場の未来をあなたの選択で変えていこう！100年後の街は個人が決める！

## 発表原稿

**デモ前の読み上げ目安　約1分**

『Mind craft』、マインドクラフトです。副題は「選択の積み重ねでつくる都市」です。

舞台は、2127年のお台場です。皆さんは、この街で暮らす一人の住民です。たとえば、荷物の受け取り予定が急に変わったら、人に相談するか、AIに任せるか。そんな日常の選択に、どんな暮らしが自分にとって心地よいかが表れます。

九つの問いの中から、一人につき四つに答えます。回答をまとめて送ると、四つのうち一つの選択に焦点を当て、その暮らしが街の中でどんな形になるかを大画面で紹介します。

四つの回答はすべて「住民の声」として積み重なり、次の人は、そのときの街を引き継ぎます。この町お台場の未来を、あなたの選択で変えていきましょう。

では、私も一人の住民として答えてみます。回答を送ったら、大画面にご注目ください。

## システム紹介

**デモ後の読み上げ目安　約40秒**（草案）

このシステムは、手元のiPad、展示用のパソコン、大画面の三つでできています。

iPadは「住民の窓」です。前面カメラで手の動きを読み取り、指でつまむ動作で選択します。画面に触れて操作することもできます。

回答は展示用のパソコンに届き、サーバーが保存して、街のどこを変えるかを決めます。決まった内容はすぐに大画面へ送られ、2127年のお台場の3D都市が切り替わります。

クラウドのサービスは使わず、すべてブースの中のパソコンで動いています。

### 全体の構成

```
iPad Air × 2（ステーションA・B）
  │  Wi-Fi（iPhoneのテザリング、ブース専用）・HTTPS
  ▼
展示用ノートパソコン（Windows）
  ├─ 回答サーバー（Node.js）── SQLite に保存
  │     │  WebSocket
  │     ▼
  └─ 3D都市（Chrome・Three.js）── HDMI ──▶ 65V型テレビ
```

### ハードウェア

| 機器 | 役割 |
| --- | --- |
| iPad Air × 2台 | 回答用の端末（ステーションA・B）。前面カメラで手の動きを読み取る |
| 展示用ノートパソコン（Windows、NVIDIA GeForce RTX 4050 Laptop GPU） | 回答サーバーと3D都市を動かす。3D表示は高性能GPUで描画する |

（準備メモ）消費電力は会場の上限500W以内に収める。[電源計画](EXHIBITION_POWER_PLAN.md)の見積もりはMac miniとルーターを前提にしているため、ノートパソコンのACアダプター定格で見積もり直す。

### ソフトウェア

| 部分 | 使っている技術 | 内容 |
| --- | --- | --- |
| 3D都市（大画面） | Three.js、TypeScript、Vite | 街全体をブラウザーで描画する。道路や植栽はコードで生成し、繰り返し出てくるものはまとめて描画する |
| 建物のモデル | Blender → GLB形式 | 居住ポッドの塔など、作り込んだ建物をモデリングして街に組み込む |
| iPadの画面（住民の窓） | TypeScript、MediaPipe（手の認識） | 手の位置を読み取り、指先で操作するカーソルとつまむ動作の選択に変える。認識はiPadの中だけで行い、映像は送らない |
| 回答サーバー | Node.js、SQLite、WebSocket | 回答を保存し、九つの問いから出す四問と、街のどこを変えるかを決めて、大画面に送る |
| 起動 | Windows用の起動スクリプト | ダブルクリック一つで、サーバー二つと3D都市のChromeを立ち上げる（全画面表示はオプション） |

### この技術を選んだ理由

選ぶときの基準は三つです。展示の現場で確実に動くこと、少人数でも作り直しを重ねられること、来場者の情報を外に出さないことです。

**1. ブラウザーで動かす（Three.js・TypeScript・Vite）**

- **インストールが要らない**　大画面はChrome、iPadはSafariでページを開くだけで動く。iPadにアプリを入れたり、App Storeで配布したりする必要がない。
- **機材が変わっても動く**　展示用のパソコンは、当初のMac miniからWindowsのノートパソコンに変わった。3D都市のコードはそのままで、Windows用の起動スクリプトを足すだけで移せた。
- **試作を速く回せる**　ゲームエンジンのようにアプリを書き出す工程がなく、コードを保存するとすぐ画面に反映される。建物や街並みの調整を何度も繰り返せる。
- **言語を一つにそろえる**　3D都市、iPadの画面、回答サーバーをすべてTypeScriptで書いている。一人でも全体を見渡して直せる。

**2. 建物はBlenderで作り、GLB形式で組み込む**

- **作り方を使い分ける**　道路や植栽のように数が多く、規則的に並ぶものはコードで生成する。主役になる建物は、形の細部や素材の質感をBlenderで作り込む。
- **GLBはThree.jsで標準的に読める形式**　形・素材・テクスチャを一つのファイルにまとめられ、変換の手間がない。

**3. 手の認識はMediaPipe**

- **iPadだけで完結する**　iPadの前面カメラだけで手を読み取れる。専用のセンサーなど、追加の機器が要らない。
- **映像を外に出さない**　認識はiPadのブラウザーの中で行い、カメラの映像は保存も送信もしない。サーバーに届くのは選んだ答えだけ。
- **外部に接続せずに動く**　認識に使うプログラムと学習済みモデルは、展示用のパソコンから配信している。
- **画面に触れずに操作できる**　大勢が同じiPadを使う展示なので、指でつまむ動作で選べるようにした。タッチ操作も併用できる。
- iPadのブラウザーでカメラを使うにはHTTPSが必要なため、ブース内の通信もHTTPSにしている。

**4. 回答サーバーはNode.js・SQLite・WebSocket**

- **準備が少ない**　SQLiteはNode.jsに標準で入っている機能を使う。別のデータベースソフトを入れる必要がなく、データは一つのファイルに収まる。
- **再起動しても回答が残る**　回答と街の状態はファイルに保存されるため、パソコンを再起動しても、それまでの街を引き継げる。
- **すぐに大画面へ届ける**　WebSocketでは、回答が届いた時点でサーバーから大画面へ知らせる。大画面が定期的に問い合わせる方式より待ち時間が短く、通信も少ない。
- **追加のライブラリが少ない**　サーバー側で使う外部ライブラリは、WebSocket用のwsとMediaPipeだけ。

**5. クラウドを使わず、ブースの中で完結させる**

- **会場の回線に左右されない**　インターネットの混雑や切断があっても、展示は止まらない。
- **回答が会場の外に出ない**　回答は展示用のパソコンの中だけに保存する。
- **費用とアカウントの管理が要らない**　有料のサービスやログインの設定がなく、当日はパソコンを起動するだけで始められる。

## デモの進行

1. 「はじめる」を押し、四つの問いに答える。最初の問いだけ読み上げ、どの選択肢を選ぶかを一言添える。

2. 回答を確認して送信し、「この選択が街のどこに表れるか、ご覧ください」と大画面に視線を移す。

3. 結果が出たら、画面に映った施設や暮らしを一言で説明する。

4. 「システム紹介」を読み上げる。時間がなければ省き、質問されたら表で答える。

**建物の切り替えを見せる場合**　九問版を初期状態から始め、荷物の問いでは「配達スタッフに相談する。」を選ぶ。デモ込みで2分の場合は、原稿の荷物の例を回答操作の場面で話す。

## 想定問答

### 心理テストですか？

住民の立場で、どんな暮らしを選びたいかを考える問いです。荷物の受け取り一つでも、人に相談したい人と、AIに任せたい人がいます。身近な選択に、安心や便利さの感じ方が表れます。

### 九問のうち、四問はどうやって決まりますか？

その時点の街の状態に合わせて、対応する場所が長く更新されていない問いから、優先して四つを出します。

### 四問答えるのに、結果が一か所なのはなぜですか？

自分のどの選択が街のどこにつながったかを追いやすくするためです。今の街と異なる選択が複数あれば、その中で最後の変更から最も時間がたっている場所を優先します。四つの回答はすべて問いごとに集計します。回答が十分に集まると、同じ問いで自分と同じ選択をした人の割合が分かります。

### 制作で一番力を入れたのは、どんなところですか？

一番力を入れたのは、今のお台場の地形や海岸線をもとに、2127年の街をデザインすることです。たとえば、上空に浮かぶ巨大なリング「空の環」を、空の交通の乗り換え拠点にしました。建物や設備は何度も試作し、街全体を見渡したときのシルエットから、近くで見たときの素材の質感まで、一つずつ調整しました。

### 建物は回答に合わせてその場で生成するんですか？

選択肢に対応する施設はあらかじめ設計しています。回答が届くと、サーバーが現在の街の状態と照らし合わせて、どのモデルを表示するかを決めます。更新された街の状態を受け取って、大画面の3D表示が切り替わります。

### 街の制作には、どんな技術を使いましたか？

街全体は、ブラウザーで3Dを表示できるライブラリ、Three.jsで作りました。道路や植栽などはコードで作って配置しています。卵形の居住ポッドが並ぶ塔など、細部を作り込んだ建物はBlenderでモデリングし、GLB形式で書き出してThree.jsの街に組み込んでいます。

### なぜゲームエンジンではなく、ブラウザーで作ったのですか？

展示の現場で確実に動かすためです。ブラウザーなら、iPadにも大画面にもアプリを入れる必要がありません。展示用のパソコンをMacからWindowsに替えたときも、街のコードは変えずに移せました。また、保存するとすぐ画面に反映されるので、建物や街並みの試作を何度も繰り返せます。

### 街全体をブラウザーで動かすために、どんな工夫をしましたか？

たとえば、植え込みや街路樹のように繰り返し出てくるものは、同じ形を使い回し、まとめて描画しています。街の中にたくさん配置しても、描画の負荷を抑えられます。

### iPadで送った回答は、どうやって大画面の街に反映されますか？

展示用のパソコンでNode.jsのサーバーを動かします。iPadはiPhoneのテザリングでパソコンと同じネットワークに接続し、Safariで回答を送ります。サーバーは回答をSQLiteに保存し、更新後の街の状態をWebSocketで大画面側のブラウザーに送ります。ブラウザーは受け取った状態をもとに、街の表示を更新します。
