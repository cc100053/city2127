## 1. 已定方向（owner，2026-11-18）

1. 城市不斷輪換 20 至 30 個已打磨的模型。每份提案**只換一個模型**。
2. 每位訪客從題庫抽 **4 題**作答，抽題依據城市目前狀態。
3. 答完後，城市**直接換成訪客所選選項的模型**，不經中間狀態。
4. 結果卡同時顯示**群眾比例**（該題全部回答中選同一選項的百分比，包括本人）。
5. **不採用**「播放時間比例＝票數比例」規則。

模擬（`~/city2127-evidence/question-rotation-sim/swap400.py`，400 次 × 120 位假訪客，非正式 ladder、非真人）：10 題 30 個模型時，約 1.5% 訪客沒有變化；每題每日變化 11–13 次；所有模型都會出場（平均計）；最長 15 位訪客內必再變；約四成變化會把少數選項放上城市。2026-11-18 以正式函數重跑（`survey/scripts/rotationSim.ts`，A／B 兩站交錯）：5 題時每 run 全部模型出場；**10 題時只有 388/400 run 全部出場**，約 3% run 有一個模型全日未出場（平均 99.9%）。

**無變化率取決於訪客答案有多一致，不是規則本身的常數。** 同一規則改用不同假設重跑（`skew.py`，同目錄）：

| 假設 | 5 題 | 10 題 |
| --- | --- | --- |
| 原設定（各題偏好 60/25/15 等，四成訪客有個人傾向） | 1.6% | 1.5% |
| 全部 70/20/10，四成個人傾向 | 2.6% | 2.7% |
| 全部 70/20/10，無個人傾向 | 6.1% | 6.2% |
| 全部 85/10/5，無個人傾向 | 23.8% | 23.7% |

答案越一致，城市越快停在多數選項，保底（3.4）越常出現。真實比例要用真人答案判斷（1.7）。

## 3. 規則（owner 2026-11-18 批准，摘要見 SPEC；3.6–3.7 為審閱後補充）

### 3.1 抽題

1. 候選＝三態齊全、已上線的題目。
2. 按「最後一次變化」由舊到新排序，相同時按題目固定次序（Q01、Q02…）決定，取前 4 題。預約時提案編號尚未存在，不能用作平手規則。
3. 抽中的題目 ID 存入草稿（預約時決定），重新載入或重試時不變。
4. 上線門檻：**至少 5 題三態齊全**；只有 4 題時每位訪客都答同一組，談不上輪換。
5. A/B 雙站：抽題**不**排除另一站已抽的題。少於 8 題時兩站必然重疊（5 題時排除後只剩 1 題），重疊改在換模型時處理（3.2 第 3 點）。

### 3.2 換模型

1. 提交時，以**當刻**城市狀態判斷（A/B 雙站可能先後改變同一題）。
2. 候選＝訪客答案與目前模型不同的題。
3. 從候選中選最久未變的一題，直接換成訪客所選的模型。**優先略過本訪客預約之後已被另一站換過的題**；只有這類題可換時才用它。其餘 3 題的答案照樣計入群眾比例，城市不變。（實作註：預約後被另一站換過的題，最後變化必然新過所有未被換過的題，所以「最久未變」排序已自動做到這點，毋須儲存預約標記。）
4. 沒有候選：保底，見 3.4。比例視答案分佈約 1.5%–24%（第 1 節表）。
5. 城市狀態由全部有效提案依次重算（fold），與現行 `ladderStep` 相同；Undo、snapshot、重新連線都由此重建，不靠隨機數。

### 3.3 群眾比例

比例＝該題在本 run 的全部回答中，選同一選項的百分比（含本人）。結果卡與 hologram「住民の声」同時顯示。文案要中性，少數選項不得寫成「輸了」。

**少人數規則：** 該題本 run 回答數未達門檻時不顯示百分比（否則第一位回答者會見到 100%，之後幾位見到 50%、33%），改用一句不含數字的文案（例：「この問いへの声は、まだ集まり始めたところです」）。建議門檻 10 票，待 owner 確認。

### 3.4 保底（owner 2026-11-18 批准）

建議：鏡頭照樣推近訪客其中一題的地塊，該模型播放一段活動動畫（例如 AUTO HUB 無人機起飛），結果卡寫「あなたの選んだ暮らしは、すでにここにあります」加群眾比例。

保底頻率取決於答案分佈（第 1 節表），可能遠高於 1.5%。因此每個上線模型的活動動畫都要經 owner 驗收，不能當作罕見情況的附屬品。

### 3.5 地塊與道路

- 地塊目錄記錄：尺寸級別、地形（海／岸／內陸）、高度上限（服務航道 30–45 m）、入口錨點、近鏡位置、旅程著陸點。新地塊用 `SCAN_LOT` 檢查淨空，並避開水上的士航線與水庭。
- 道路網固定，不隨模型改變。每塊地塊有一條固定支路，終點是入口平台。每個模型的主入口必須落在平台上；前庭細節（花槽、導光線、收邊）屬於模型，隨模型更換。
- 各有地塊的題目，未輪到的地塊顯示打磨過的空置態（水面、公園或平台），支路終點照樣可達。

### 3.6 新舊系統並存

現行 version4 四題系統須完整運作至 6.6 開新 run。新題組用到的地塊與現行系統重疊：Q08 用 SW `changeSites.sw`、Q03 用 `DRAWER_HOUSING`、Q02 令水の棚田隨投票，2.7 又凍結 SE、SW 與 district 舞台。

- 第 2、3 階段每一步的完成標準都包括「version4 run 外觀不變」（前後截圖對照）。
- 此項阻擋第 2 階段，不阻擋第 1 階段。

直接換模型代表**一位訪客的答案決定他看到的那一個變化**。這改變了 AGENTS.md 與 SPEC「居民敘事」的現行原則：訪客「不是單憑自己答案決定累積變化的規劃者」，以及 G1 階梯與四題提案的描述。Owner 已接受這個取捨；「眾人之一」的部分改由群眾比例（3.3）表達。

## 5. 風險

- **模型數量與性能：** 現有 GLB 最大約 14 MB（SE district）、13 MB（蛋艙塔）、8.5 MB（水の棚田）。20–30 個模型同時常駐，需要 6.4 實測；2.3 的預載策略是後備。
- **雙站同時提交：** 少於 8 題時兩站必然抽中重疊的題；3.2 以提交當刻狀態判斷並優先略過預約後已被換過的題，後提交者仍可能觸發保底。1.7 模擬兩站交錯量度。
- **保底頻率：** 無變化率隨答案一致程度上升（約 1.5%–24%，第 1 節）；上線前以真人答案分佈估計。
- **新舊系統並存：** 新地塊與現行 Meter 地塊重疊，版本切換未做好會改變 version4 展覽（3.6）。
- **城市反映近期意見多於群眾：** 已由 owner 接受，以群眾比例補足（1.4、3.3）。
- **企劃組研究數據：** 抽題跟城市狀態走，每題回答數不平均；如作研究統計須註明。
- **題目與模型主題重疊：** Q01-C 與 Q07-C 都是自動配送；Q06-C 與 Q08-C 都是模組。上線前要令每個模型只屬一題。
